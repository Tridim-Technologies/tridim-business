# Dependency maintenance

This guide covers routine and security updates for the Tridim Business core repository. Dependency changes use the normal issue, branch, pull request, CI, and review workflow. Updates are not merged automatically.

## Manifests and lockfiles

| Area | Dependency manifest | Committed lockfile | CI install check |
|---|---|---|---|
| Python backend and development tools | `pyproject.toml` | `uv.lock` | `uv sync --locked` |
| React application | `frontend/package.json` | `frontend/package-lock.json` | `npm ci` followed by the production build |
| GitHub Actions | `.github/workflows/*.yml` | Not applicable | Workflow checks and GitHub Actions validation |

Dependabot checks `uv`, npm, and GitHub Actions weekly. It opens reviewable pull requests with a limit of five open version-update pull requests per ecosystem. The configuration does not group all routine upgrades or auto-merge them. GitHub security alerts and security-update pull requests are separate repository security features; verify that dependency graph, Dependabot alerts, and Dependabot security updates are available and enabled in repository settings.

## Reviewing an update

For every update pull request:

1. Read the pull request summary and inspect both the manifest and lockfile changes. Lockfiles are generated by their package managers; do not hand-edit them.
2. For a security update, read the linked advisory and confirm which dependency and affected versions are involved. Prioritize fixes according to severity and whether the affected code path is used; record any blocker and follow-up rather than silently dismissing the alert.
3. For a major version or changed constraint, review the upstream release notes and compatibility with Python 3.12, Django 6, Node 24, and the application code before accepting the change.
4. Confirm the required CI checks pass. Do not merge a dependency update with failing, skipped, or still-running required checks.
5. Merge through the repository's normal pull request workflow. Never enable automatic merging for dependency updates.

Security updates should be reviewed as they arrive rather than waiting for the routine weekly version-update cycle. No response-time guarantee is defined here.

## Intentional dependency changes

Use the package manager to change manifests and lockfiles together:

- Python runtime dependency: `uv add <package>`
- Python development dependency: `uv add --dev <package>`
- Frontend dependency: `cd frontend && npm install <package>`

Use the corresponding remove command when deleting a dependency. Review the resulting manifest and lockfile diff, then run the same checks used by CI. For a known vulnerability, set the minimum version at or above the advisory's patched release; a safe lockfile alone does not prevent future installs from selecting affected versions. Do not widen version constraints solely to make an automated update pass; decide compatibility deliberately.

## Local validation

From the repository root, validate the Python project and documentation with:

```sh
uv sync --locked
uv run python backend/manage.py check
uv run python backend/manage.py makemigrations --check --dry-run
uv run ruff check backend
uv run ruff format --check backend
uv run python backend/manage.py test accounts customers quotations invoicing health hr
```

Validate the React application with:

```sh
cd frontend
npm ci
npm run build
```

The pull request workflow runs these checks, Markdown lint, and prototype validation. Keep `pyproject.toml` and `uv.lock`, and each npm `package.json` and `package-lock.json`, in sync.
